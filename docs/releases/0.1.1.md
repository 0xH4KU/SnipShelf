# SnipShelf 0.1.1

Capture confirmation now opens a small floating preview near the selection,
restoring the desktop instead of covering it with a full-screen review canvas.

- **Keep Clip** or Return saves the cutout once. Escape or closing the preview
  cancels without saving.
- **Refine** returns to the frozen image with the outline, zoom, pan, and toolbar
  position preserved. Undo restores the previous selection and its preview.
- Fixed capture-toolbar dragging by measuring the gesture in the stationary
  canvas coordinate space, preventing feedback from the moving toolbar.
- The same compact confirmation is used by screen capture and Crop a Copy.

## Download and install

`SnipShelf-0.1.1-arm64.zip` requires **Apple Silicon and macOS 26 or newer**.
Quit SnipShelf, unzip the download, replace `SnipShelf.app` in Applications, and
reopen it. Clips remain in the app's local storage.

The app is **ad-hoc signed and not notarized**, with no developer certificate
or Team ID. If macOS blocks the first launch and you trust the download, use
**System Settings → Privacy & Security → Open Anyway**.
[Apple's instructions](https://support.apple.com/102445) explain the exception;
managed Macs may restrict it. Screen capture also requires screen-recording
permission in Privacy & Security.

Verify the download with its companion checksum file:

```sh
shasum -a 256 -c SnipShelf-0.1.1-arm64.zip.sha256
```

## Validation and limits

All 34 tests passed, including the optional light/dark rendering check. Native
AppKit tests cover preview placement, editor visibility, refinement, undo,
exactly-once saving, and cancellation. The direct Computer Use plugin verified
toolbar displacement in Crop a Copy.

The full screen-capture flow remains unverified because macOS denied recording
access on the test build. macOS 26 runtime, downloaded-app Gatekeeper handling,
and trackpad feel still need manual verification; tests ran on macOS 27 with
Apple Silicon. See the [usage guide](../usage.md) and
[validation notes](../validation.md).
